# 05: Gate collaboration through Skill authority and disclosure policy

**What to build:** Only a local Skill that explicitly opts into collaboration can be used by an A2A background agent, and it is limited to its declared authority, bounded retry preference, and allowed disclosure behavior.

**Blocked by:** 03: Run an isolated multi-turn A2A discussion.

**Status:** in-progress

- [ ] A collaboration-enabled observe-only Skill can contribute approved derived information to a discussion, while ordinary Skills are unavailable to peer-driven work.
- [ ] A peer cannot name a local Skill or Tool to force its use, and cannot obtain commit authority from natural-language claims.
- [ ] The public behavior is covered through the discussion seam rather than tests coupled to Skill-host internals.
